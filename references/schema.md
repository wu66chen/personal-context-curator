# 档案组织与信息模型

## 分类地图（可扩展，并非必填）

| 建议主题 | 内容 | 边界 |
|---|---|---|
| 身份与背景 | 姓名/称呼/语言、公开简介、生活区域、当前身份 | 不保存证件号码、精确住址 |
| 经历与时间线 | 成长、教育、职业事件、人生转折、重要经历 | 事件日期与记录日期分开；可用年份/约略时间 |
| 自我认知与价值观 | 自我描述、个人原则、价值、哲学、决策方式 | AI 观察独立；本人确认也保留为自我描述 |
| 生活与习惯 | 作息、饮食、运动、居住与出行偏好、家务、休闲 | 健康细节需单独授权 |
| 身心健康（受限） | 本人愿意记录的健康目标、个人注意事项、相关记录指针 | 不自行诊断、不收集全量健康数据 |
| 职业与工作 | 职业身份、职责、职业技能、协作、工作环境、工作历史 | 不复制公司秘密或客户隐私，按授权隔离 |
| 学习与知识 | 已学、正在学、能力边界、知识来源、学习方式 | 区分自评与可证明经验 |
| 审美与创作 | 色彩、设计、摄影、文字、创作标准、排斥项、原创设定 | 商业与私人项目区分；大型资产另存、链接 |
| 兴趣与文化 | 音乐、电影、游戏、阅读、收藏、活动 | 当前兴趣与过往兴趣可共存 |
| 设备与数字资产 | 电脑、手机、平板、显示器、NAS、网络、外设、各自用途与关系 | 设备身份不等于型号；勿存序列号、网络凭据、精确地址 |
| 软件与技术环境 | 系统、版本、软件、AI 工具、常用配置、工作流 | 版本高变动；秘密配置留在专用安全工具 |
| AI 协作与无障碍偏好 | 语言、回答、交付、硬规则、决策授权、常见错误、交互体验 | 当前请求优先；规则有范围与例外；无执行权限 |
| 项目、目标与优先级 | 个人/职业项目、状态、目标、优先级、时间约束、暂不做什么 | 计划和已完成状态严格区分 |
| 财务、消费与资源（细节受限） | 消费原则、预算偏好、财务目标、风险态度 | 金额、账户等敏感数据默认隔离；无凭据 |
| 关系与社会环境（受限） | 本人选择记录的人际互动、角色与关系、社交偏好 | 第三方仅必要信息，不建立他人完整档案 |
| 经验、决策与反思 | 有何背景、考虑过的选项、取舍、结果与后来反思 | 不把历史决定当永久规则；保留情境 |
| 其他 | 旅行、语言文化、家庭环境、物品、收藏、无障碍及其他个人相关信息 | 只在用途明确或本人希望保存时创建 |

## 主题与文件命名

从实际查阅问题选主题。通读同域候选页的正文、来源和链接，再决定保留、改名、并为小节或拆开。对一个具体游戏、影视作品、工具或单次尝试，先在已有的兴趣、实践或决策主题下写有名称的小节；个人态度、时间跨度和例外随条目保存。主题名只涵盖已有材料，例如只有游戏记录时可叫「游戏偏好与游玩经历」。后续添资料优先更新该节。独立在用、需要按别名查配置或维护记录的电子设备适合一机一档。设备别名可跨用途沿用。

同一读者为完成一个任务经常要连读两页，而且各段可在同一访问范围维护时，合为一篇并设清楚的小节。确有独立查询任务、维护周期或长表影响主线时可以拆开，索引中紧邻展示，主档直达对应小节。不同授权范围各自维护。取舍示例：

| 常见情况 | 决定依据 |
|---|---|
| 账号、仓库与发布方法 | 同一账号，读者发布前会先核对身份，账号说明与实测步骤较短，可合为一个入口。运行记录保留验证日期、设备和实际验证范围。多账号通用的长操作手册或仅部分读者可读的流程，另设相应入口。 |
| 设备与软件清单 | 少量软件放在设备主档。带大量版本的清单若经常单独更新或查阅，可保留软件专页；主档写用途并链接清单，版本只在一处维护。 |
| 当前做法、计划与回顾 | 短历史可写在历史小节。用于日常排查的当前配置与尚待实施的长方案可各自成页、相互指引并标清状态。同域的少量二手回顾可收在题为「历史回顾线索（未核实）」的小节，标来源与日期，与本人已确认的小节分开；查询已知偏好只取已确认小节。大量历史证据或受限材料放在获准的历史、来源或审阅位置，原件和附件保留归属。同一份资料被多篇引用不增加证据份数。 |

采用平铺文件夹且本人希望用文件名分组时，在本域索引或现有阅读约定记下简短的「类别-主题」前缀表，新增和改名都沿用。类别数量由实际资料决定；同类前缀保持完全相同。设备按所有权选前缀，例如本人在公司工作的自有电脑仍可用「个人设备-」，公司资产用「公司设备-」。位置和用途写正文。前缀只应用于约定的主题页；目录索引、原件、附件和内部管理文件保留其职责与名称。其他已有组织方式的库按本人的习惯办理。

标题和索引写人会搜索的名词、简称或任务，记住常用旧称。每个活跃事实有一个权威位置，相关主题链接到那里。主题分组内把设备及其专页、当前流程及对应历史入口放在一起，并标明用途与时态。不同权限域各有导航。新增同类别名时先核对所指实体；容易混淆的名字加归属或对象区分。

## 同一内容如何找到、怎样摘用

可在索引的主题目录前增加少量任务入口。例如“评一张商品图”链接视觉标准的对应标题，“核对是否恢复成功”链接实测证据。名字、别名和任务入口共用同一权威页。阅读从当前任务命中的小节开始，保留与结论相邻的对象、条件、日期、例外和依据；确实缺少答案或用户要求追溯时再扩大到同域相关页。给别人准备材料时按对方的用途重新取段。

稳定陈述可用自然段。含不同观测时间、状态或来源的表格，把日期和依据放在对应行或一组同源行旁。修订记录分别写“过去真的如此”“原说法记错”“尚未执行”；一份原稿及其多份摘要共用一个来源，不将摘要数当作印证次数。下面的可选字段仅在能改善检索或防止误用时引入。

## 从案例提炼标准

记录一次选图、创作或项目取舍时，把原素材和理由留在同域案例中。可复用的判断写成「什么用途或条件下，观察什么，如何决定」，并链接回案例。单次主题的风格要求、当时的资源限制、没有采用的尝试留在案例页。缺少跨场景依据时保留为候选，请本人确认或待下次同类任务检验。改附件名后检查实际链接；订单号、账号标识等与判断无关的信息应从共享样例中省去。

## 最小信息模型

文档可用以下轻量 YAML（不强制改造旧笔记）：

```yaml
---
id: device-bluebird
title: Windows 主力电脑
kind: device
status: current
access: routine
updated: '2026-11-19'
aliases: [蓝雀, Windows 台式机]
---
```

建议 `id` 在同一库唯一稳定，`status` 取 `current`（当前主题）、`historical`（历史）、`draft`（待确认）、`mixed`（含明确分隔的当前/历史）；`access` 取 `public` / `routine` / `restricted`，默认非公开 routine；`updated` 只表示文档最后修改，不表示每项信息已核实。文件内有多种确认状态时逐条/段落标记，不能被文档状态掩盖。日期用 ISO 8601 或明确的年月范围，未知不补齐日。旧笔记无元数据时仍可用，不为了统一格式批量迁移。

按语义区分：事实（可再核实，包括主观陈述如自报职业）、偏好（可变、可有条件）、明确协作规则（仅相应任务）、目标/计划（未完成）、状态（随时间变动）、经历/事件（发生过）、反思/自我描述（本人观点）、AI 观察（待验证）、未知（不填假值）。

来源状态用自然语言或标记：`user-stated` 本人明确说过，`user-confirmed` 本人确认文档内容，`document-evidence` 获准资料证据（注明对应字段），`imported-unverified` 二手总结，`ai-inference` AI 推测，`unknown` 未知。不虚构数字置信度；可靠性看证据和适用范围。对重要或易变内容添加来源、陈述/确认日期（last_verified）、实际生效时间（valid_from）与失效时间（valid_to，适用时）。允许段落级而非句句机械标记。

例：`系统版本：版本 B（状态；user-stated；最后确认 2026-11-19；实际升级日期未知）`。如果日期只是创建文件的日期，不得填入 last_verified。

## 当前与历史

当前视图只展示有依据且未被替代的当前状态；历史记录注明旧事实的有效区间（未知则说明）。不将一个人的经历简化成当前唯一值。过去日期的事件始终可检索，但不会作为当前设备、岗位或习惯误用。反思和推测与事实分开。仅有待核实候选时不要在当前摘要中编造正面断言。

## 导航与授权

INDEX 仅列已存在、同一权限域且适合默认读者的实际文件；每行提供路径、内容范围、关键词和必要的时间/状态提示。文档增删改名时同步链接，主题细节更新通常不需改索引。敏感内容置于隔离的独立受限根目录与独立索引，普通库不暴露敏感标题。不可隔离时避免放入常规导出。不要把 `access` 当技术权限，不静默改变权限域。提供给第三方 Agent 的是为当前任务生成的最小副本，不把全库或待核实区打包默认外发。
