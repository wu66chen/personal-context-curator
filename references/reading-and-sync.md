# 阅读首页与跨设备验收

## 先弄清用户平时在哪里改、在哪里读

列清当前主档、用户选定的共享子集、同步服务及阅读端。确认现有笔记库的真实路径和当前使用的同步方式；同名目录可能分属不同库。已经给过的答案直接沿用。写明交付覆盖了哪些主题以及截止时间，区分一次性导出的快照与持续维护的内容。用户已有同步链路时复用它；如需另建通道、更改传播方向或覆盖现有笔记，应先说明影响。

## 把原索引做成阅读入口

保留一个稳定的索引和可直接打开正文的普通 Markdown 链接。用户需要可视化时，可以在同一索引内增加主题、文件修改时间和全量列表视图，例如嵌入 Obsidian Bases。用现有分类或路径起步；旧笔记缺属性时也要能找到。新类别可落入兜底分组。确认目录内的来源、中转、私密材料和索引自身不会被动态视图一并收录。混合访问范围的目录应使用获准条目的清单或已验证的分域边界；视图过滤只控制展示。

从读者实际使用的应用打开入口，切换每个承诺的视图，将可见条目与预期清单比对，打开代表性链接。回到普通 Markdown 检查备用导航；增删、改名或调整标题时同时维护手写链接。按修改时间排序只回答文件何时变动，事实的核实日期见正文。

## 按实际观察报告同步

| 能核对的位置 | 能给用户的结论 |
| --- | --- |
| 来源与本机目标 | 本地已生成或已复制，给出路径、文件范围及内容比对结果。 |
| 同步服务 | 通过已有授权入口读回指定修订，比较正文或内容哈希。若只有日志，注明日志记录的事件及时间。 |
| 目标设备 | 在正确的库中找到落盘文件，再从阅读应用打开首页和正文。分别报告到达设备、成功显示的结果。 |

只有前两项证据时，把第三项留作未直接核实。看不到某页，先从目标端区分目录选错、文件尚未到达、文件存在但未展示，再查增量同步状态。核实断点靠日志或检查点，估计耗时说明采样时段和计量单位。优先保留本地未上传的改动和可用进度。清库、覆盖或改换链路需单独决定。验证更新传播时优先读回本次真实改动；若需一次性测试笔记，在获准范围内使用虚构内容并验证清理结果。同步和独立备份各有验收条件，恢复能力以实际还原演练为据。
