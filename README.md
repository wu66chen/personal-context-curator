# Personal Context Curator · 个人上下文档案

给经常与 AI 合作的人使用的 Agent Skill。把分散在对话、笔记和文件里的个人经验整理成自己持有的 Markdown 档案，需要时只给下一位读者相关的几页。

举个例子。你以前说“喜欢留白”，实际指的是给读书会做讲义。几个月后新开一次对话，用这条记录做讲义时，可以连同当时的用途一起取出；为节庆海报选风格时，这条偏好仍有它的适用范围。

## 适合谁

- **经常更换对话、模型或电脑的人。** 想让新对话接上自己的工作方式，也希望能亲自打开文件、修正一条过时的记录。
- **积累了不少案例的创作者和知识工作者。** 希望把一次取舍背后的理由留下，逐渐分清哪些经验能复用，哪些只适用于当时。
- **同时维护个人、工作或私人资料的人。** 同一份档案给自己查阅、给同事交接、给 Agent 使用时，可以分别选取内容和读者。

## 第一次使用

在支持本地 Skills 的 Codex 环境中安装。下面是 Windows PowerShell 示例，使用默认的个人 Skills 目录，要求本机有 Git。已有同名安装时先核对来源及本地改动。自定义了 Codex 数据目录时改用对应的 `skills` 路径。

```powershell
git clone https://github.com/wu66chen/personal-context-curator.git "$HOME/.codex/skills/personal-context-curator"
```

也可以在 GitHub 点 **Code → Download ZIP**，把解压后含有 `SKILL.md` 的那层目录放进宿主的个人 Skills 目录，并命名为 `personal-context-curator`。新开一个 Codex 对话，指定一个与 Skill 安装目录分开的资料目录。例如：

> 使用 $personal-context-curator，在当前工作目录的「我的档案」里建库。先记一条：给读书会做讲义时，我偏好大字号，便于现场朗读。以后只在做讲义时使用这条偏好。

打开新库的 `INDEX.md`，应能找到记录这项偏好的主题页。下次说“投影版还需要更大的字号”时，Agent 会核对原记录，再把新条件补到同一处。仓库本身只放 Skill 规则、模板和虚构样例。你的个人资料放在你选定的另一处目录里。

## 三个常用场景

| 你可以这样说 | 完成后能拿到什么 |
| --- | --- |
| “帮我写提示词，让熟悉我的聊天 AI 回顾我的学习经历。” | 一段可直接转发的提示词，约定交付一份有文件名、可下载的 Markdown，聊天只发文件。你交回后，Agent 对照已确认内容，剩下的问题可以集中填表，也可以保留未知。 |
| “把这组选图理由整理一下，下次评别的图也用得上。” | 本次项目的取舍留在案例；有依据的通用标准连同适用条件写入主题页，可追溯到案例。 |
| “我想在另一台电脑上阅读选定的档案，看看同步到哪了。” | 明确本次选了哪些页，复用已有笔记库和同步方式。交付时分别说明本机文件、同步服务和目标阅读端各核对到哪一步。 |

## 需要哪些工具

| 环节 | 需要什么 | 可选工具或替代方式 |
| --- | --- | --- |
| 本地建库、更新 | 能加载 Skill、读写指定目录的 Agent，以及用户授权的位置 | 本项目在 Codex 上维护。其他兼容宿主可按其 Skills 加载规则使用。日常建档没有 Python、数据库或 API 密钥依赖。 |
| 阅读档案 | 能打开 UTF-8 Markdown 的工具 | 文本编辑器即可。想按主题、修改时间切换视图时，可以在已有索引里嵌入 Obsidian Bases，同时保留普通链接。 |
| 回顾旧对话 | 能提供来源的已有材料 | ChatGPT 是一种选择，其他能访问相关历史的助手也可以；已有笔记或本人直接说明同样可用。仅聊天的环境可交付文件，再由本地端应用。 |
| 多设备使用 | 仅在需要时，使用本人授权的传输方式 | 可以交付一次性副本，也可以沿用已有同步服务。备份能否恢复需另行验证。 |
| 安装与开发 | ZIP 可手工安装；Git 用于克隆或贡献 | Python 3.9+ 仅用于运行仓库中的合成验收脚本。 |

## 档案如何维护

一个索引可以从设备名、主题或常做的任务链接到同一条记录。每次更新先区分“后来变了”“当时记错了”和“这次是例外”。回忆、推测和本人确认分开记录。读者、用途和权限决定哪些材料可以进入交付副本；密码和密钥交给凭据管理器。文件夹分类方便查找，实际隔离取决于宿主权限。

按需查阅[主流程](SKILL.md)、[分类与命名](references/schema.md)、[交接与回顾](references/cross-agent-acquisition.md)、[采访方式](references/interview.md)、[阅读与同步验收](references/reading-and-sync.md)和[维护与恢复](references/maintenance.md)。[设计依据](references/research.md)说明哪些做法借鉴了研究，哪些来自日常使用中的取舍。
